# Internationalisation (EN / FR / AR)

Langues : `en` (défaut et repli), `fr`, `ar` (RTL). Toute autre langue → `en`.

## Convention de clés

`<zone>.<nom>` en `snake_case`, ex. `order.hold_label`, `payment.remaining_due`.

Zones : `login`, `floor`, `order`, `payment`, `kitchen`, `fiscal`, `admin`, `receipt`, `errors`, `messages`, `common`.

Placeholders : `{nom}` côté web et serveur ; `%@`, `%lld`, `%d` côté iOS. Une traduction garde **exactement**
les mêmes placeholders que l'anglais (les contrôles ci-dessous échouent sinon). Côté iOS, les montants sont entourés
des isolats Unicode U+2066/U+2069 : les conserver autour du même placeholder dans chaque langue.

## Où ajouter une clé

| Couche | Fichiers | Note |
|---|---|---|
| Web | `src/RestaurantPos.Api/wwwroot/i18n/{en,fr,ar}.json` | `t('zone.nom', { x })` dans `app.js`, ou `data-i18n*` dans `index.html` (sans placeholder) |
| iOS — PosKit | `ios/Packages/PosKit/Sources/PosKit/Resources/{en,fr,ar}.lproj/Localizable.strings` | `.strings` et non `.xcstrings` : `swift build` ne compile pas les String Catalogs |
| iOS — app | `ios/RestaurantPOS/Resources/Localizable.xcstrings` | `en`, `fr`, `ar` à l'état `translated` |
| Serveur | `src/RestaurantPos.Infrastructure/Localization/SharedResource{,.fr,.ar}.resx` | `Texts.Get(culture, "zone.nom", ("x", valeur))` |

Toujours ajouter la clé dans les trois langues. Ne pas traduire : données saisies (produits, tables, opérateurs…),
textes marqués `// nf525-texte-fixe`, noms de langue dans les sélecteurs, sigles (PIN, TVA/VAT, NF525, Z, X, FEC, Happy Hour), `€`.

## Repli

Clé absente dans la langue → valeur anglaise ; absente en anglais → la clé elle-même est affichée.
Placeholder sans valeur → laissé tel quel. Chiffres occidentaux (0-9) partout, y compris en arabe.

## Vérifications

```bash
node scripts/i18n-check.mjs --no-french        # web : clés utilisées ↔ définies (en, fr, ar), valeurs vides, placeholders, français en dur
dotnet test tests/RestaurantPos.Infrastructure.Tests --filter "FullyQualifiedName~TextsTests"   # serveur
cd ios/Packages/PosKit && swift test --filter LocalizationTests   # PosKit + catalogue de l'app : en/fr/ar complets, formats identiques
```

Montants en arabe : toujours gauche-droite (`direction: ltr; unicode-bidi: isolate` ou `<bdi dir="ltr">` sur le web,
isolats U+2066/U+2069 sur iOS) ; la phrase qui les contient suit la direction de la page.

## Relecture

La version arabe doit être relue par un arabophone avant toute mise en production.
